The problem

Everyday decisions are scattered

Decisions, tasks, money, and habits live in different notebooks and apps. Nothing connects a decision to the task, the budget, or the habit that follows it — and nothing explains why one option is better than another.

Our answer

  • One system: a C++ console app and a website that share the same online PostgreSQL database.
  • One login: every user sees only their own data.
  • AI help: six Gemini assistants that explain their recommendations instead of just giving an answer.

Architecture

Four parts, one database

  • Shared database: a decision saved in the console appears on the website, and vice versa.
  • Fail fast: if the database is unreachable, server and console stop with an error — they never silently fall back to local files.
  • Hosting: Render requires a card, so there is no Render service — the demo runs on localhost, and VPS hosting is planned.

Formulas (verified)

  • Priority = urgency × 2 + importance × 3 (max 50)
  • Compare = benefit × 3 − cost − risk
  • Multi-task: highest urgency first, within energy / time budgets
  • Budget: remaining < 0 → “Reduce expenses.”

Security

Your data stays yours

  • First user is ADMIN. Later users are USER. There is no promote / demote / password-reset endpoint by design.
  • Per-user isolation. Every read is owner-filtered; asking for another user's row returns 404, never the data.
  • Passwords are stored as PBKDF2 hashes, never in plain text. Minimum 8 characters, with a letter and a digit.
  • Sessions are in-memory tokens, 12-hour expiry. A server restart logs users out.
  • Login rate limit: 5 failed attempts per username in 300 seconds, then 429.
  • AI history is strictly per-user; the Gemini key is sent only as the x-goog-api-key header and never appears in a response, log, or the database.
  • Input is data, not instructions. The AI instruction is a fixed server-side constant; user text is quoted data.

Known limits (stated honestly)

  • No hosted backend yet. The demo runs on localhost, so the server must stay running on the demo PC; VPS hosting is planned. Postgres mode is mandatory so the console and the website share one database.
  • The default Gemini model is gemini-3-flash-preview; gemini-2.0-flash and gemini-2.5-flash are retired, and gemini-3.8-flash (production target) was answering 503 on 2026-11-09.
  • The Python server is a local fallback only: no AI (501), no Postgres.
